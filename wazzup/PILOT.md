# Пилот обработки чатов для alfa330

Раздел «Чаты ОП → Верификаторы», аккаунт `op`. Отправка текста, файлов и SSE доступны
только пользователю с логином `alfa330`, который уже имеет доступ
к разделу. Ограничение повторяется на сервере для каждого метода; остальные
пользователи продолжают пользоваться архивом. Отправка в два известных канала
Global запрещена сервером. Архив Global остаётся доступен для просмотра.
Статусы учётной записи `fired`/`dismissal` закрывают доступ. Признак
`users.is_active` обозначает работу оператора на линии и не ограничивает админа.

## Запуск

Нужен обычный деплой backend и frontend из одного изменения. При старте
`Database._init_db` создаёт таблицы, функции и триггеры из `pilot_schema.py`.
Дополнительных секретов нет: отправка использует существующий `WAZZUP_OP_API_KEY`,
слушатель PostgreSQL — обычные `POSTGRES_*` приложения. Ключ в браузер не передаётся.
Вебхук Wazzup должен, как и прежде, присылать входящие, исходящие и статусы.

После деплоя: войти как alfa330, открыть «Чаты ОП → Верификаторы», выбрать
активный личный WhatsApp-чат вне Global. Над списком появится состояние связи,
под перепиской — поле ответа. Enter отправляет, Shift+Enter добавляет строку. Первое сообщение
следует проверять с согласованным тестовым получателем; автоматические проверки
этого изменения клиентам ничего не отправляют.

Успех POST означает принятие Wazzup. «Отправлено», «Доставлено», «Прочитано»
появляются по вебхуку. Это статусы прочтения клиентом исходящего сообщения;
открытие входящего чата не отправляет команду «прочитано» в WhatsApp.

## Доставка и восстановление

- Один PG LISTEN на процесс, затем рассылка по SSE. Нет запросов к базе на
  каждый heartbeat. События PostgreSQL видны только после COMMIT.
- Максимум 8 потоков пилота на процесс; каждый занимает поток Waitress.
  Скрытая вкладка закрывает SSE. Переавторизация каждые 120–140 секунд,
  повторное соединение с задержкой, heartbeat 20 секунд, watchdog 65–75 секунд.
- Статусы применяются прямо из SSE без SELECT и повторного HTTP чтения переписки.
  Новые/изменённые сообщения слушатель загружает вместе со сводкой чата одним
  запросом на пакет до 100 сообщений, независимо от числа подписчиков.
  На каждого клиента запросов нет. Если подписчиков нет, загрузка не выполняется.
  Буфер ограничен 2048 событиями/8 MiB; редкие события больше 256 KiB восстанавливаются
  через HTTP. Только при отсутствии данных события действует задержка восстановления
  переписки 350 мс и списка 1 секунда.
  После переподключения перечитывается отображаемый диапазон истории;
  ответ ограничен 2000 сообщениями, при переполнении остаются последние 2000.
  Ошибки чтения повторяются с паузой, без непрерывного опроса.
- Исходящая попытка фиксируется в outbox до HTTP-запроса. Повтор того же UUID
  не отправляет ещё одно сообщение, включая таймаут и перезапуск приложения.
  Wazzup сам проверяет `crmMessageId` лишь в течение 60 секунд:
  [документация v3](https://wazzup24.com/help/api-en/sending-messages/).
- После неопределённого результата черновик блокируется. «Проверить отправку»
  проверяет прежнюю попытку. Для нового сообщения нужно явно подтвердить
  проверку переписки. Черновик и UUID сохраняются в sessionStorage этой вкладки.
- Ранние статусы ждут сообщения в отдельной таблице до двух суток;
  delivered/read не откатываются поздними sent/error. История остаётся 45 дней.
  Текст outbox очищается по тому же сроку, UUID остаются для защиты от дублей.

Пилот включает текстовые ответы, отправку файлов, входящие/исходящие сообщения,
изменения, удаления и статусы из вебхуков. Назначение/блокировка чата оператору
и аккаунт «Поток» в этот пилот не входят.

### Отправка файлов

Скрепка перед `/` выбирает один файл. Выбор только загружает вложение: оператор
проверяет имя и размер, затем нажимает отправить или убирает файл. Документы,
аудио и видео ограничены 10 МБ, фотографии — 5 МБ; сервер проверяет размер,
расширение и содержимое. Файл отправляется через `contentUri` без `text`:
Wazzup не допускает их одновременно. Уже набранный текст остаётся черновиком.

`POST /api/wazzup/pilot/uploads` принимает multipart с `account`, `channelId`,
`chatId`, `clientUploadId` и `file`. Возвращает только ID и метаданные вложения.
`POST /api/wazzup/pilot/send` принимает `attachmentId` с пустым `text` и обычным
`clientMessageId`. ID привязан к сотруднику и конкретному чату; произвольные
ссылки браузер не передаёт. Повтор неопределённой отправки проверяет прежний
outbox и не делает новый запрос Wazzup, даже после истечения срока вложения.

Хранилище использует существующий GCS-клиент и
`GOOGLE_CLOUD_STORAGE_BUCKET_TASKS` (либо `GOOGLE_CLOUD_STORAGE_BUCKET`). Объекты
закрытые, префикс `wazzup/pilot/uploads/`, срок подготовки — 24 часа; для Wazzup
создаётся ссылка на 30 минут. Ссылка не попадает в ответы браузеру, черновики
или локальную историю сообщений. Просроченные объекты удаляются небольшими
пакетами в фоне при последующих загрузках; обход всего bucket не выполняется.
Срок 24 часа ограничивает отправку: физическая очистка происходит при следующих
загрузках и не гарантируется ровно в момент истечения срока.
Одновременно в процессе допускаются две загрузки, лимит сотрудника — 12/мин.

## Шаблоны, эмодзи и непрочитанные

### Интерфейс и внутренние комментарии

Лента центрирована и ограничена шириной 1040 px (раньше 900 px): входящие слева,
исходящие справа внутри общей колонки. Вертикальный интервал прежний. Имя
сотрудника показано отдельной строкой над первым пузырём серии его сообщений.
Входящее, комментарий, другой/неизвестный автор и новый день начинают новую
серию. При наличии сравниваются ID авторов, иначе — их нормализованные имена.
Исходящие мягко-зелёные;
статусы отображаются рядом со временем без разделительной точки: одна серая
галочка — отправлено, две серые — доставлено, две синие — прочитано. Ожидание
обозначается часами, ошибка — значком предупреждения. Подсказка и доступное
имя сохраняют текст статуса. Двойное нажатие на тело сообщения выбирает его
для ответа; вложенные кнопки, цитаты, медиаплееры и удалённые сообщения исключены.

На каналах WABA (`transport=wapi`) подсказка над полем ввода появляется только
через 24 часа после последнего известного входящего сообщения клиента. Она
предлагает возобновить переписку одобренным шаблоном WABA из Wazzup (кнопка `/`).
Сервер возвращает `lastInboundAt` в существующих ответах истории и обновления:
максимум `COALESCE(wazzup_dt,dt)` по входящим этого аккаунта/канала/чата, независимо
от страницы истории. Новое входящее SSE сразу обновляет время и убирает подсказку;
исходящие, комментарии и статусы окно не продлевают. Один таймер до истечения
окна и проверка при возврате на вкладку работают без HTTP-опроса.
Для обычного WhatsApp и при неизвестном времени входящего подсказка скрыта.
Окончательную доступность отправки по-прежнему проверяет Wazzup.

Эмодзи в сообщениях, цитатах, превью чатов и комментариях используют тот же
Apple-набор 16.0.0, что панель выбора. PNG загружаются лениво с закреплённого
CDN-адреса и занимают фиксированное место. Исходный Unicode остаётся в DOM для
копирования; составные эмодзи, оттенки кожи и флаги не разделяются. Лента не
загружает код панели выбора. Неизвестные последовательности остаются текстом,
при недоступности CDN используется системное отображение.

Превью фотографий резервирует область 280×210 px с ограничением по ширине
пузыря. Размер одинаков до загрузки, после неё и при ошибке: декодирование
изображения не раздвигает ленту. Изображение полностью вписывается в область.

Иконка заметки в шапке открывает компактное поле «Комментарий · только команде».
Поле начинается с одной строки и увеличивается по мере ввода до 144 px.
Обычное поле отправки на это время скрывается. Комментарий сохраняется только
в `wazzup_chat_notes`, показывается компактной кремовой карточкой с автором над ней и
временем, не меняет очередь ожидающих ответа. Сервер определяет автора и время;
UUID попытки защищает от повторного создания при таймауте. Текст до 4000 символов.
Комментарии не записываются в `wazzup_messages`, outbox отправки или очередь
Syntony, поэтому не могут быть отправлены водителю этими интеграциями.

API GET/POST `/api/wazzup/pilot/notes` использует тот же доступ alfa330,
аккаунт `op`, исключает Global и требует существующий чат. GET возвращает
последние 200 комментариев и поддерживает курсор `beforeId`; интерфейс показывает
последние 200. Метаданные новых заметок передаются через PG NOTIFY, текст
подгружается общим SSE-слушателем отдельным пакетным запросом. Переподключение
восстанавливает заметки. Автоматическая очистка клиентской истории за 45 дней
не удаляет внутренние заметки.

Каналы сворачиваются кнопкой в панели до полосы логотипов; настройка сохраняется
для оператора и аккаунта. Справочник и кадрирование логотипов берутся из доступного
пользователю пространства вики «Таксопарки» обычным API с проверкой прав. Два
запроса на загрузку справочника, без опроса при каждом событии. Неоднозначные
совпадения и недоступные логотипы заменяются инициалами канала.

`/` в начале ответа или `+ Шаблоны` открывает поиск. Одобренные текстовые WABA
шаблоны загружаются через `GET /v3/templates/whatsapp` и отбираются по каналу.
Кеш на процесс — 10 минут, при сбое копия не старше часа с предупреждением.
Переменные заполняются до вставки; оператор видит текст, а Wazzup получает
документированный `@template:` код. Проверка канала/переменных выполняется сервером
до создания outbox. Код остаётся частью неизменяемой попытки отправки.

Текущий API-ключ даёт WABA. Обычные быстрые шаблоны через публичный API
`/v2/templates/wz` требуют партнёрского `client_access_token`. Они импортируются
из авторизованного интерфейса Wazzup в `wazzup_imported_templates` и доступны всем
номерам обработки в аккаунте `op`, без фильтра по каналу. Это снимок каталога,
не автоматическая синхронизация. Тексты не хранятся в Git. Источники:
[WABA](https://wazzup24.com/help/api-en/whatsapp-business-api-templates/),
[обычные шаблоны](https://wazzup24.ru/help/api/templates-wz/).

Перенос: браузерная выгрузка `{workspace: "6757-7677", total: N, data: [...]}`
содержит все страницы обычных шаблонов (`guid`, `name`, `text`, `files`).
`scripts/import_wazzup_templates.py outputs/<export>.json` проверяет полноту,
декодирует HTML entities один раз и показывает количество изменений без записи.
`--apply` импортирует через `POST /api/wazzup/pilot/templates/import`, доступный
только супер-администратору с обычной JWT-аутентификацией. Повторный GUID обновляет
существующую запись, сохраняя её ID; отсутствующие в пакете записи не удаляются.
Весь пакет валидируется до транзакции; предел — 1000 шаблонов. Шаблоны с файлами
помечаются неподдерживаемыми, чтобы случайно не отправить только часть содержимого.
Постоянная подсказка о доступности убрана, ошибки обновления WABA отображаются.

`+ iCORE` создаёт общий текстовый шаблон в `wazzup_quick_templates` (до 250).
Собственные шаблоны можно изменять и удалять; в Wazzup они не публикуются.
Только WABA помечены значком WhatsApp, обычные текстовые шаблоны — без значка.
Панель закрывается по клику снаружи и Escape, в том числе после открытия через `/`.
Во время сохранения или удаления закрытие блокируется до завершения запроса.

Ссылки HTTP(S) и `www` в сообщениях открываются в новой вкладке; HTML entities
вроде `-&gt;` декодируются в текст без выполнения разметки. В превью внутри кнопок
ссылки остаются текстом. Аудио воспроизводится собственным плеером с перемоткой,
временем и скоростями 1×/1.5×/2×. Загрузка начинается по Play, одновременно играет
одна запись; при смене чата плеер останавливается и освобождает аудио.

В панели эмодзи — рисунки Apple, поиск на русском, категории и оттенки кожи.
Отправляется Unicode; вид отправленного символа зависит от устройства получателя.
Каталог загружается отдельным файлом при простое видимой вкладки или наведении/
фокусе на кнопку, а при экономии трафика — по запросу. Первые 24 картинки прогреваются
с четырьмя параллельными запросами. PNG с закреплённой версией CDN кешируются год;
после открытия панель остаётся смонтированной. При ошибке картинки остаётся Unicode.

Общий счётчик означает «Ожидают ответа». Открытие и прокрутка чата его не снимают.
Ответ оператора через Wazzup/iCORE закрывает входящие, отправленные до ответа;
кнопка «Ответ не нужен» явно закрывает текущую очередь. Условная запись по
последнему входящему messageId защищает новое входящее от случайного сброса.
Изменения передаются команде через SSE. Global и «Поток» исключены.

`wazzup_chat_read_state` хранит счётчик и время последнего ответа;
`wazzup_unanswered_messages` — только ID/время ожидающих входящих. Повтор webhook,
редактирование, статусы доставки и анонимное приветствие интеграции не добавляют
новых входящих. Ответ определяется по authorName/authorId, sentFromApp или outbox
iCORE; для анонимной сторонней интеграции webhook не позволяет отличить бота от
человека. Ошибка отправки не закрывает очередь; поздний ответ не закрывает более
новые входящие. Миграция один раз пересчитывает только уже отслеживаемые чаты,
сохраняя ручные нули; весь архив непрочитанным не становится.

«Ответ не нужен» — общее состояние iCORE, не команда прочтения WhatsApp и не
синхронизация ручной отметки в Wazzup. Публичный API возвращает общий счётчик
пользователя, но не предоставляет документированного сброса отдельного чата:
[счётчики Wazzup](https://wazzup24.com/help/api-en/unanswered-counter/).

## Ответы и редактирование черновика

Стрелка у сообщения выбирает цитату. Отправка использует документированный
`refMessageId`; сервер проверяет принадлежность исходного сообщения чату.
Цель ответа сохраняется в outbox и входит в проверку повторного UUID.
Собственные цитаты видны в истории/refresh/SSE, даже если оригинал не загружен
в текущую страницу; удалённый текст оригинала не возвращается.

Кнопки RU/ҚАЗ и перефраз меняют только черновик. Используется существующий
Vertex-провайдер приложения, модель `WAZZUP_DRAFT_AI_MODEL` (по умолчанию
`gemini-3-flash-preview`). В ИИ передаётся только выбранный черновик, не история.
Два параллельных запроса на процесс и 12 запросов на пользователя в минуту;
HTTP-таймаут провайдера 12 секунд, клиентский 25 секунд. Результат можно отменить;
изменение текста или переход в другой чат отменяет применение старого результата.
Числа, ссылки и email проверяются до замены. Одобренные WABA-шаблоны не редактируются.

Поле ввода начинается с одной строки и растёт до 160 px. Кнопка шаблонов — `/`.
Текст сообщений 16 px; переписка ограничена 900 px, ввод — 1040 px на широких экранах.
Дата первого видимого сообщения появляется при прокрутке и исчезает через 900 мс;
поиск видимого сообщения не сканирует всю ленту, скролл тонкий.

WABA-шаблон передаётся как `@template:` и может тарифицироваться. Wazzup указывает,
что текстовый шаблон внутри активного 24-часового окна может быть отправлен как
обычное сообщение; с октября 2026 для сервисных сообщений действует лимит
1000 бесплатных на номер в месяц. Итог зависит от типа, страны и условий Wazzup:
[тарификация](https://wazzup24.ru/help/payment/whatsapp-business-api-charging/),
[изменения октября](https://wazzup24.com/help/waba/updates-october-2026/).
Обычные быстрые ответы ещё не перенесены: браузер этой сессии недоступен.

Проверка этой версии: 203 Python-теста (22 subtests), 62 JavaScript-теста,
production-сборка Vite. Реальные вызовы ИИ на трёх вымышленных черновиках:
перефраз 3.61 с, перевод на казахский 1.58 с, на русский 1.65 с.
Read-only предварительный расчёт на рабочей БД: 86 чатов/422 входящих →
7 чатов/10 входящих, ручные нули сохранены. Это снимок до выкладки, не счётчик
на текущий момент. Визуальная проверка и отправка цитаты реальному получателю
ещё не выполнялись; автоматические проверки не отправляли WhatsApp-сообщений.

## Просмотр вложений и OCR — 07.10.2026

PDF и изображения в пилотных каналах открываются внутри чата. Просмотрщик и
PDF.js 6.4.299 с локальным worker загружаются только после клика по файлу.
Есть страницы, масштаб, выделение текста, маленькая кнопка скачивания и панель
копирования текста текущей страницы. Иные форматы и закрытые паролем PDF
можно открыть оригиналом; встроенный просмотр этих форматов не поддерживается.

Если фотографии и документы идут подряд от одного отправителя, просмотрщик
показывает снизу ленту этой группы: миниатюры фотографий, названия документов,
текущее вложение и стрелки переключения. Клавиши ←/→ переключают вложения;
кнопки страниц PDF работают независимо. Текстовое сообщение, комментарий,
новый день, другой отправитель или пауза больше 10 минут разделяют группы.
Группа собирается из уже загруженной переписки, до 100 вложений вокруг открытого.
Через сервер загружается только выбранный файл; миниатюры фотографий используют
те же ссылки, что лента чата, с ленивой загрузкой. При переключении прерываются
загрузка и OCR предыдущего файла, освобождаются PDF и blob URL, сбрасываются
масштаб и страница. Неподдерживаемый формат остаётся карточкой с оригиналом,
без автоматического скачивания через сервер.

`GET /api/wazzup/pilot/attachment` принимает только account/channelId/chatId/messageId.
Сервер проверяет пользователя, принадлежность и удаление сообщения, затем читает
сохранённый URL только на HTTPS `store.wazzup24.com`; редиректы проверяются заново.
Объём до 20 MiB, два одновременных скачивания, не более 30 запросов в минуту на
пользователя. Полные файлы не сохраняются в приложении. Текстовый слой PDF читается
в браузере; это не вызывает ИИ и не добавляет запросов серверу.

Для сканов и фото оператор явно запускает распознавание. Браузер рисует только
текущую страницу (длинная сторона до 1920 px) и передаёт JPEG в
`POST /api/wazzup/pilot/attachment-text` вместе с ID сообщения и номером страницы.
Сервер повторно проверяет доступ, ограничивает изображение 4 MiB/12 MP и удаляет
метаданные при перекодировании. OCR через существующий Vertex: два запроса
параллельно, восемь в минуту на пользователя, результат до 32 000 символов.
Текст и файл не пишутся в БД/логи, OCR выполняется только по кнопке. Результат
сохраняется лишь в памяти открытого просмотрщика (до 20 страниц), его нужно
проверить перед использованием. Смена страницы/чата отменяет применение старого
результата. Модель задаётся `WAZZUP_OCR_MODEL`, по умолчанию `gemini-3-flash-preview`.

Казахский перевод теперь использует обычную уважительную речь: «жіберіңізші»,
«тексеріліп жатыр», без книжных оборотов и добавленного сленга. Имена кнопок в
кавычках сохраняются. Четыре вымышленных черновика проверены настоящим ИИ;
суммы/время и намерение сохранены. OCR на вымышленном изображении с русским и
казахским текстом занял 3.39 с; номер заявки, сумма, дата и телефон совпали.
Проверки этой версии: 184 Python-теста и 22 subtests, 78 JavaScript-тестов,
production-сборка. Среди проверок — реальный PDF.js parse/render тестового PDF,
загрузка шрифтов, CMap/WASM, отмена запросов и отсутствие автоматического OCR.
Подключённого браузера для визуальной проверки нет. Клиентские вложения в ходе
этих проверок не скачивались; использованы вымышленные файлы.
