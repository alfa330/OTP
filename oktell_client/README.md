# iCORE Oktell — клиент АТС с обязательными новостями

Оператор скачивает программу с портала, вводит **учётную запись iCORE** — и
дальше всё происходит само: клиент получает от сервера логин с паролем кабинета
Oktell, входит в АТС за оператора и показывает обязательные объявления поверх
рабочего окна.

Зачем отдельная программа. Сегодня объявление живёт во вкладке портала, а
оператор смотрит в веб-клиент Oktell: до человека оно доходит, только если
вкладка открыта. Здесь и АТС, и окно объявления — одно приложение, поэтому
«показать и не пустить к работе» больше не зависит от того, куда он смотрит.

## Запуск

```
npm install
npm start          # обычный запуск
npm run stub       # заглушка портала и АТС на localhost (отдельным окном терминала)
npm run selftest   # сквозной прогон против заглушки, печатает отчёт и выходит
```

Конфиг — `config.json` рядом с программой, образец в `config.example.json`:
адрес портала, адрес АТС, селекторы полей входа и список состояний «занят».
Пустой `api_base_url` не беда: экран входа спросит адрес сам.

⚠️ Из встроенного терминала VS Code не запускать: он ставит
`ELECTRON_RUN_AS_NODE=1`, и Electron стартует обычным Node. Лечится
`env -u ELECTRON_RUN_AS_NODE npm start`.

## Как это устроено

**Вход.** `POST /api/login` с `auth_transport: bearer` — куки не годятся,
приложение ходит с другого origin и SameSite их не приложит. Токен обновляется
сам через `/api/auth/refresh`: смена длится смену, а токен доступа меньше, и
экран входа посреди разговора недопустим.

**Учётка АТС.** `GET /api/operator/oktell_account`. Пароль оператор не знает и
знать не должен — его заводит руководитель в «Настройках SIP → Таксопарки».
Не отдалась (409 — ещё не выдали) — пускаем вводить руками, а не запираем
перед пустым экраном.

**Страница Oktell живёт дочерним видом**, а не в том же документе, что наш
интерфейс. Так окно объявления убирает её с экрана целиком одним вызовом — это
и есть блокировка работы. Наложить свой слой поверх чужой страницы нельзя: она
в другом процессе и про наш DOM не знает. Спрятанному виду вдобавок схлопывается
размер: если `setVisible` однажды окажется пустышкой, вид нулевого размера всё
равно не примет ни клика, ни клавиши.

**Статус оператора берём у самой страницы**, обёрткой `window.WebSocket`
(`preload-oktell.js`). Наш сервер вычитывает те же статусы из SQL-прокси раз в
несколько секунд, а прокси бывает недоступен минутами — за это время разговор
успевает начаться и кончиться. Обёртка обязана стоять ДО скриптов страницы,
поэтому это preload с `contextIsolation: false`, а не вставка после загрузки:
первая версия вставляла скрипт на `did-finish-load` и не поймала ни одного
кадра. Node странице при этом не достаётся.

**Правило показа.** Объявление ждёт, пока оператор в разговоре: окно закрывает
собой клиент АТС, и посреди консультации это отняло бы у него интерфейс. Но
ждёт не вечно — если состояние так и не пришло (другая версия АТС, вендор
переименовал поле, сокет не поднялся), через `unknown_state_grace_seconds`
объявление показывается всё равно: молчаливо проглоченное объявление хуже
показанного не вовремя. Освободился — окно появляется сразу, не дожидаясь
следующего опроса.

**Подтверждение проверяет сервер.** Выдержку кнопки, ответы теста и право
вообще подтверждать эту новость решает `POST /api/news/<id>/read`; клиент
только рисует секунды и показывает ответ. Считать «сколько прошло» самим нельзя
— часы на машине оператора свои.

## Что проверено

`npm run selftest` поднимает окно и прогоняет против заглушки 18 проверок: вход,
выдачу учётки, очередь объявлений, три отказа сервера подряд (рано → неверный
тест → успех), приход статуса из настоящего веб-сокета поддельной страницы,
подстановку учётки, сокрытие и возврат вида АТС и все ветки правила показа.

Чего проверка не покрывает: настоящий веб-клиент Oktell. Селекторы полей входа
и точные имена состояний «занят» снимаются одним живым сеансом на рабочей
машине — до тех пор в конфиге стоят догадки, и обе живут в файле именно
поэтому.
