# Ручка знаний iCORE для ИИ Syntony

Версия 1 от 29.10.2026. Адрес API: `https://otp-2-fos4.onrender.com`.

Ваш ИИ отвечает водителям таксопарка. Когда в его базе знаний ответа нет, он
присылает нам **таксопарк и вопрос**, а мы возвращаем **фрагменты** нашей базы
знаний: куски статей, карточку парка, адреса и телефоны офисов, комиссии по
городам. Готового ответа мы не отдаём — его составляет ваш ИИ по фрагментам.

Права у вызова ровно такие, как у оператора техподдержки водителей (СЗоВ):
ваш ИИ получает то же, что видит наш оператор, и ничего сверх этого.

## Коротко

- Один вызов — один таксопарк и один вопрос. Информация отдаётся **только по
  этому парку**: акции, офисы и телефоны у парков разные.
- Ключ передаётся в заголовке `X-Api-Key`. Ключ выпускает iCORE и показывает
  один раз; храните его на сервере, в клиентский код не кладите.
- Ответ `status: ok` — фрагменты есть; `status: no_data` — у нас тоже нет
  данных, вопрос уже передан нашим супервайзерам, они дополнят базу знаний.
- Каждый вызов записывается в журнал: время, парк, вопрос, что отдали.

## Проверка ключа

```http
GET /api/knowledge/ping
X-Api-Key: <ключ>
```

```json
{
  "status": "ok",
  "key": "Syntony",
  "acts_as": {"role": "operator", "department": "СЗоВ — Служба заботы о водителях", "department_code": "szov"},
  "limits": {"per_minute": 60, "max_question_chars": 1000, "max_fragments": 20}
}
```

## Список таксопарков

```http
GET /api/knowledge/parks
X-Api-Key: <ключ>
```

```json
{
  "parks": [
    {"id": 5, "slug": "global", "name": "Global", "city": null},
    {"id": 1, "slug": "itaxi", "name": "iTaxi", "city": null}
  ]
}
```

В запросах лучше передавать `park_id`: число не меняется, а название парка
редакторы могут поправить.

## Поиск

```http
POST /api/knowledge/search
X-Api-Key: <ключ>
Content-Type: application/json

{"park_id": 5, "question": "Какие акции сейчас действуют для водителей?", "limit": 8}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `park_id` | да, либо `park` | id парка из `/api/knowledge/parks` |
| `park` | вместо `park_id` | slug или название парка, без учёта регистра (`"global"`) |
| `question` | да | вопрос водителя, до 1000 знаков; на русском или казахском |
| `limit` | нет | сколько фрагментов статей вернуть, 1–20; по умолчанию 8 |

Передавайте вопрос как его задал водитель, вместе с контекстом, если он есть
(«в Алматы», «у меня ИП»). Телефон, ФИО и другие личные данные водителя для
поиска не нужны — в вопрос их не включайте.

### Ответ

```json
{
  "status": "ok",
  "request_id": "7e4c0d6c-0d8c-4a9b-9b1d-2f0b2c6b7c11",
  "park": {"id": 5, "slug": "global", "name": "Global"},
  "question": "Какие акции сейчас действуют для водителей?",
  "fragments": [
    {
      "rank": 1,
      "kind": "article",
      "article_id": 33,
      "title": "Все акции",
      "heading": "Розыгрыши Такси.Про 2026",
      "text": "Актуальные акции 2026 №: 1; Парк: Все парки, кроме Ноль такси; Город: Все города; Даты: 21.09.2026 - ?; Название: 2 недели без комиссии парка; ...",
      "chunk_id": 4812,
      "score": 0.3123,
      "similarity": 0.8471,
      "found_by": ["words", "meaning"],
      "park_match": "all_parks",
      "outdated": false
    }
  ],
  "notes": [],
  "degraded": false,
  "perimeter": {"articles": 50}
}
```

| Поле ответа | Что это |
|---|---|
| `status` | `ok` — фрагменты есть; `no_data` — данных нет (см. ниже) |
| `request_id` | номер вызова; называйте его, если что-то пошло не так |
| `park` | парк, по которому собран ответ |
| `fragments` | фрагменты по убыванию полезности: сначала справочники, потом статьи |
| `notes` | предупреждения словами, например: в вопросе назван другой парк |
| `degraded` | `true` — поиск шёл только по словам, без векторов (временно хуже находит синонимы) |
| `perimeter.articles` | сколько статей доступно вызову |

### Фрагмент

| Поле | Что это |
|---|---|
| `kind` | `article` — кусок статьи; `park` — карточка парка (комиссия, сайт, головной офис, телефоны); `office` — офис из справочника; `offices` — сводка офисов по городам; `city` — комиссии Яндекса в городе; `cities` — таблица по городам; `classifier` — какой тариф положен автомобилю |
| `title`, `heading` | статья и путь заголовков внутри неё (или вкладка справочника и запись) |
| `text` | сам текст фрагмента, как он есть в базе знаний |
| `article_id`, `chunk_id` | ссылки на статью и кусок; для справочников пусто |
| `score`, `similarity` | оценки поиска: `similarity` — смысловая близость к вопросу от 0 до 1 |
| `found_by` | чем найден: `words`, `meaning`, `typo`, `title`, `directory` |
| `park_match` | `named` — запрошенный парк назван во фрагменте; `general` — парков не названо, информация общая; `all_parks` — фрагмент про все парки или со списком исключений |
| `outdated` | `true` — архивная или истёкшая информация; отвечать по ней как о прошлом |
| `office` | только у `kind: office`: `{"id", "kind": "park" | "partner", "partner_label", "note"}` |

## Как вашему ИИ пользоваться фрагментами

- Отвечать только по фрагментам. Если нужного в них нет — так и сказать
  водителю и предложить связаться с оператором; не додумывать.
- Фрагменты `kind: park`, `office`, `city` — живые данные справочника (адреса,
  телефоны, графики, «сейчас открыт»). Они точнее текста статей, если
  расходятся — верить справочнику.
- `park_match: all_parks` — внутри текста строки вида `Парк: …`. Перед ответом
  сверяйте, что строка относится к запрошенному парку: «Все парки, кроме Ноль
  такси» для Ноль такси не действует.
- `office.kind: partner` — партнёрская точка (брендирование, сервис), **не офис
  таксопарка**; так и говорите водителю. У таких записей в `office.note`
  стоит «Партнёрская точка, не офис таксопарка».
- Статьи написаны для операторов: в них бывают шаги в CRM и внутренние ссылки.
  Водителю пересказывайте условия и порядок действий для него, а не
  инструкции оператора.
- Вопрос на казахском задавать можно: поиск его понимает, но тексты фрагментов
  русские — переводит ваш ИИ.
- `notes` читайте: если водитель спросил про другой парк, ответ всё равно
  ограничен парком вызова.

## «Данных нет»

```json
{
  "status": "no_data",
  "request_id": "…",
  "park": {"id": 5, "slug": "global", "name": "Global"},
  "question": "…",
  "fragments": [],
  "notes": [],
  "degraded": false,
  "perimeter": {"articles": 50},
  "message": "Данных нет",
  "question_logged": true
}
```

Вопрос уже ушёл супервайзерам техподдержки: они ответят и допишут статью, и в
следующий раз фрагменты найдутся. Повторять тот же вопрос сразу бессмысленно —
данные те же; повторы мы считаем, лишних заявок они не создают. Водителю в этом
случае лучше предложить оператора.

## Ошибки

Тело ошибки: `{"error": "…", "code": "…", "request_id": "…"}` (`request_id` — у
вызовов, дошедших до разбора запроса).

| HTTP | `code` | Что значит | Что делать |
|---|---|---|---|
| 400 | `KNOWLEDGE_API_BAD_REQUEST` | тело не JSON, нет вопроса или парка, вопрос длиннее 1000 знаков, `limit` вне 1–20 | исправить запрос; текст в `error` |
| 401 | `KNOWLEDGE_API_UNAUTHORIZED` | ключа нет, он неверный или отозван | проверить заголовок; запросить новый ключ |
| 403 | `KNOWLEDGE_API_PARK_UNAVAILABLE` | парк в архиве — по нему не спрашивают | взять парк из `/api/knowledge/parks` |
| 404 | `KNOWLEDGE_API_PARK_NOT_FOUND` | такого парка нет среди открытых ключу | взять парк из `/api/knowledge/parks` |
| 429 | `KNOWLEDGE_API_LIMIT` | больше 60 вызовов за минуту | подождать `Retry-After` секунд |
| 429 | `KNOWLEDGE_API_BUSY` | слишком много одновременных вызовов | повторить через `Retry-After` секунд |
| 500 | `KNOWLEDGE_API_FAILED` | внутренняя ошибка | повторить позже; если повторяется — написать нам с `request_id` |
| 503 | `KNOWLEDGE_API_NOT_CONFIGURED` | ручка на сервере не развёрнута | написать нам |

## Пределы

- 60 вызовов в минуту на ключ, 4 вызова одновременно на всех.
- Вопрос — до 1000 знаков, тело запроса — до 16 КБ, фрагментов — до 20.
- Обычное время ответа — до 2 секунд; ставьте таймаут 15 секунд и не
  повторяйте вызов, пока предыдущий не завершился.

## Безопасность и журнал

- Ключ действует от имени оператора техподдержки: черновики, статьи «только
  для сотрудников» и списки с личными данными в ответ не попадают.
- Ключ только в заголовке `X-Api-Key`: не в адресе, не в теле, не в
  `Authorization`. Только HTTPS.
- Утечка ключа — сообщите нам, ключ отзывается сразу; взамен выпускается
  новый. Смена ключа: мы выпускаем новый, вы переключаетесь, старый отзываем.
- Журнал вызова: время, IP, парк, вопрос, ссылки на отданные фрагменты (без
  их текста), исход, длительность. Хранится 90 дней. Текст вопроса видят
  наши сотрудники — поэтому личные данные водителя в вопросе не нужны.

## Примеры

```bash
curl -s https://otp-2-fos4.onrender.com/api/knowledge/ping -H "X-Api-Key: $KEY"

curl -s https://otp-2-fos4.onrender.com/api/knowledge/parks -H "X-Api-Key: $KEY"

curl -s https://otp-2-fos4.onrender.com/api/knowledge/search \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"park_id": 5, "question": "Где офис в Алматы и как он работает?"}'

curl -s https://otp-2-fos4.onrender.com/api/knowledge/search \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"park": "global", "question": "Жолаушы затын салонда қалдырды, не істеу керек?", "limit": 5}'
```
