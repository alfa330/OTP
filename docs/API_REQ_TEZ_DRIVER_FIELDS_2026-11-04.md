**Запрос в TEZ APP: два поля в POST /drivers/first-orders**

Новых эндпоинтов не нужно. В уже работающий `POST /drivers/first-orders` добавить два поля ответа — `registered_at` и `last_order_at`. Изменение обратно совместимое: запрос, лимиты и прежние поля не меняются.

**Зачем**
Отчёт «Воронка ОП» отдела продаж Тез КЦ:
1. «Уже зарегистрированы» и «Зарегистрировались после контакта» — нужна дата регистрации водителя. Сейчас `month_first_order_at = null` не отличает «аккаунта нет» от «аккаунт есть, но не ездил».
2. «Вышли к заказам после диалога» — нужно знать, был ли заказ после звонка. Сейчас видим только первый заказ месяца и последний заказ до месяца, поэтому звонок в конце месяца и поездка в начале следующего теряются.

**Эндпоинт** — без изменений
`POST https://api.tezapp.org/drivers/first-orders`
Авторизация — заголовок `X-Integration-Token`, до 100 водителей в запросе, водитель ищется по телефону.

```json
{"month": "2026-11", "drivers": [{"full_name": "Иванов Иван", "phone": "+77012345678"}]}
```

**Ответ** — два новых поля в каждой строке

```json
{
  "drivers": [
    {
      "full_name": "Иванов Иван",
      "phone": "+77012345678",
      "month_first_order_at": "2026-11-08T09:52:05+05:00",
      "last_order_before_at": "2026-06-19T10:20:27+05:00",
      "registered_at": "2026-11-05T14:03:11+05:00",
      "last_order_at": "2026-11-20T18:41:00+05:00"
    }
  ]
}
```

- `registered_at` — string (ISO 8601 с часовым поясом) или `null`: дата и время регистрации водителя в TEZ APP; `null` — аккаунта нет.
- `last_order_at` — string (ISO 8601 с часовым поясом) или `null`: последний завершённый заказ водителя на момент запроса, за всё время; от `month` не зависит; `null` — заказов не было.

**Правила контракта**
1. Новые поля присутствуют в каждой строке всегда; нет значения — `null`, а не отсутствие поля.
2. Прежние поля и их смысл не меняются — текущая интеграция продолжает работать без правок.
3. Даты — в том же формате, что сейчас: ISO 8601 со смещением (`+05:00`).
4. Удаление или переименование полей — только с предупреждением заранее и через новую версию эндпоинта. В августе поле `previous_month_first_order_at` пропало без предупреждения: ошибки не было, а расчёт выплат операторам тихо изменился.
5. Нагрузка не растёт: те же запросы с той же частотой.

**Что уточнить**
1. Регистрация — это создание аккаунта или его подтверждение (активация)? Нужна дата, с которой водитель может принимать заказы.
2. Если водитель регистрировался повторно, какая дата придёт — первая или последняя?
3. Заказ — только завершённая поездка, отменённые не считаются? Исходим из этого и для `last_order_at`, и для текущих полей.

**Как проверим**
Отправим 10–20 номеров, по которым даты регистрации и заказов известны из вашей админки, и сверим ответ.
