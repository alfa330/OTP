**Запрос в TEZ APP: поиск аккаунтов по номеру и по ID**

Один новый метод для колл-центра техподдержки. Оператору звонит водитель или клиент — iCORE
открывает карточку звонка и должен сразу показать, чей это номер.

**Зачем**
1. По номеру звонящего показать оператору все аккаунты TEZ APP на этом номере — водителей и
   клиентов, — чтобы он выбрал нужный, а не искал его в админке руками.
2. По ссылке на аккаунт из админки (`/admin/drivers/<id>`, `/admin/clients/<id>`) получить его
   профиль: человек часто звонит не с того номера, на который зарегистрирован, и оператор
   прикладывает ссылку сам.
3. Город аккаунта нужен для отчёта по причинам обращений в разрезе городов.

**Метод**
`POST https://api.tezapp.org/accounts/lookup`
Авторизация — тот же заголовок `X-Integration-Token`, что у `/drivers/first-orders`.

Два вида запроса, ответ у обоих одного вида.

По номеру — все аккаунты, у которых этот номер сейчас стоит в профиле:

```json
{"phone": "+77012345678"}
```

По виду и ID — один аккаунт (`type`: `driver` или `client`, `id` — число из адреса админки):

```json
{"type": "driver", "id": 12345}
```

**Ответ**

```json
{
  "accounts": [
    {
      "type": "driver",
      "id": 12345,
      "full_name": "Иванов Иван",
      "phone": "+77012345678",
      "city": "Алматы",
      "status": "active",
      "registered_at": "2026-11-05T14:03:11+05:00",
      "last_order_at": "2026-11-10T18:41:00+05:00"
    },
    {
      "type": "client",
      "id": 67890,
      "full_name": "Иван",
      "phone": "+77012345678",
      "city": "Алматы",
      "status": "active",
      "registered_at": "2025-03-02T09:15:40+05:00",
      "last_order_at": null
    }
  ]
}
```

- `type` — `driver` или `client`; `id` — тот же, что в адресе админки.
- `full_name`, `city`, `status` — строка или `null`. `status` — как в админке (активен, заблокирован,
  на проверке…): покажем оператору как есть.
- `registered_at`, `last_order_at` — ISO 8601 со смещением или `null`, смысл тот же, что в
  `/drivers/first-orders`.
- Аккаунтов нет — `{"accounts": []}` с кодом 200, а не ошибка.
- Другие полезные оператору поля (машина, тариф, баланс) можно добавлять — незнакомые поля мы
  не теряем, а покажем в карточке.

**Правила контракта**
1. Поля присутствуют всегда; нет значения — `null`, а не отсутствие поля.
2. Неверный номер, вид или ID — 400; неверный токен — 401.
3. Нагрузка: один запрос на звонок линии техподдержки (десятки–сотни в сутки), по одному номеру
   не чаще раза в минуту. Отвечать нужно быстро — запрос идёт, пока оператор держит трубку:
   мы ждём ответа не дольше 6 секунд.
4. Удаление или переименование полей — только с предупреждением заранее.

**Что уточнить**
1. Ищутся ли удалённые и заблокированные аккаунты? Нам они нужны: по заблокированному звонят чаще
   всего. Тогда это видно в `status`.
2. Если у водителя в профиле несколько номеров — поиск идёт по всем или только по основному?

**Как проверим**
Отправим 10–20 номеров и ID, по которым аккаунты известны из вашей админки, и сверим ответ.
