**Метод**

`POST https://api.tezapp.org/accounts/lookup`
Заголовок `X-Integration-Token` — тот же токен, что у `/drivers/first-orders`.

Запрос — один из двух видов.

По номеру (писать можно как угодно: `+7 701 234 56 78`, `87012345678`, `7012345678`):

```json
{"phone": "+77012345678"}
```

По виду и ID из адреса админки (`type`: `driver` или `client`):

```json
{"type": "driver", "id": 12345}
```

**Ответ** — код 200, одинаковый для обоих видов:

```json
{
  "accounts": [
    {
      "type": "driver",
      "id": 12345,
      "full_name": "Иванов Иван",
      "phone": "+77012345678",
      "city": "Алматы",
      "status": "verified",
      "status_text": "Проверен",
      "registered_at": "2026-11-05T14:03:11+05:00",
      "last_order_at": "2026-11-10T18:41:00+05:00",
      "deleted_at": null,
      "matched_by": "phone"
    },
    {
      "type": "client",
      "id": 67890,
      "full_name": "Иван",
      "phone": "+77012345678",
      "city": "Алматы",
      "status": "active",
      "status_text": "Активен",
      "registered_at": "2025-03-02T09:15:40+05:00",
      "last_order_at": null,
      "deleted_at": null,
      "matched_by": "phone"
    }
  ]
}
```

- Аккаунтов нет — `{"accounts": []}` с кодом 200.
- Все поля есть всегда, нет значения — `null`. Даты — в `+05:00`, бывают с долями секунды.
- Неверный номер (не казахстанский мобильный), неверный `type` или `id`, номер и `id` в одном
  запросе — 400. Неверный токен — 401.

**Поля**

- `id` — тот же номер, что в адресе админки (`/admin/drivers/<id>`, `/admin/clients/<id>`): по
  нему строится ссылка на аккаунт.
- `status` — код для логики, `status_text` — подпись как в админке, показываем оператору как есть:
  - `deleted` (Удалён), `blocked` (Заблокирован);
  - у клиента иначе `active` (Активен);
  - у водителя иначе статус проверки: `verified` (Проверен), `waiting_verification` (Ожидает
    проверки), `new` (Новый), `incomplete_profile` (Профиль не заполнен), `profile_in_edit`
    (Профиль на правке), `car_photos_expired` (Фото авто устарели), `rejected` (Отклонён),
    `rejected_by_iin` (Отклонён по ИИН), `active_limited` (Допущен с ограничениями).
- `registered_at` — когда создан аккаунт.
- `last_order_at` — начало последней завершённой поездки: у водителя — как водителя, у клиента —
  как пассажира. Отменённые не считаются.
- `deleted_at` — когда аккаунт удалён, у остальных `null`.
- `city` — город из профиля; `phone` — номер из профиля (у удалённого — тот, что был до удаления).
- `matched_by` — почему аккаунт в ответе:
  - `phone` — номер сейчас в профиле или был в нём до удаления аккаунта;
  - `previous_phone` — водитель раньше пользовался этим номером и сменил его; в `phone` — нынешний;
  - `id` — найден по виду и ID.

Порядок в ответе: аккаунты с этим номером сейчас, затем удалённые, затем водители, сменившие номер.

**Что важно знать**

1. Заблокированные и удалённые находятся и по номеру, и по ID. На одном номере бывает несколько
   аккаунтов сразу: водитель и клиент; удалённый старый и новый, созданный после удаления.
2. Историю смены номера водителей TEZ APP хранит с 16.11.2026 — более ранние смены по прежнему
   номеру не найдутся. У клиентов истории номера нет: клиент ищется только по номеру в профиле.

**Что с этим делает карточка** (`client_cards/`)

- Найденные по номеру аккаунты закрепляются за номером звонка и показываются в порядке TEZ APP;
  несколько — выбирает оператор, единственный подставляется сам. Найденный по прежнему номеру сам
  не подставляется, пока с этого номера по нему не обращались.
- В строке аккаунта — город, статус (удалён, заблокирован, отклонён — красным; ждёт проверки или
  допущен не полностью — жёлтым), дата удаления, номер из профиля, если звонят не с него; у
  выбранного — регистрация и последняя поездка.
- 400 на номер — «не казахстанский мобильный»: для карточки это «аккаунтов нет», а не сбой.
- Аккаунт, который TEZ APP перестал находить по номеру, с номера снимается — если по нему с этого
  номера не обращались.
- Ссылка оператора на несуществующий аккаунт не привязывается: TEZ APP отвечает, что такого нет.
