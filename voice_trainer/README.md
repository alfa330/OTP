# Тренажёр: раздел OTP

Голосовой разговор с ИИ и разбор после него. Раздел тестовый, доступен только
супер-админу, живёт по адресу `?view=voice_trainer`.

Два режима одной механики:

* **Водитель** — ИИ играет водителя такси, человек тренируется отвечать как
  оператор, в конце второй ИИ выставляет оценку по критериям сценария.
* **Наставник** — наоборот: человек спрашивает, ИИ отвечает как опытный оператор,
  опираясь на базу знаний. Свой поиск здесь НЕ строится: вызывается движок
  чат-помощника вики — тот же периметр статей (человек слышит только то, что ему
  разрешено читать), тот же гибридный поиск, тот же генератор.

Собран на том, что уже оплачено: распознавание — Soniox, база знаний — вики.
Голосовой платформе (Vapi, Retell, ElevenLabs) платить не за что: она продаёт
именно эти слои.

## Где что лежит

| Файл | Что делает |

Тесты: `pytest tests/test_trainer_schema.py tests/test_trainer_access.py`,
`npm run test:trainer`.

## Куда идёт звук

Микрофон подключается **напрямую к Soniox** по временному ключу на 10 минут:
поток непрерывный, и гонять его через наш сервер значило бы платить лишним кругом
на каждом кадре. Озвучка идёт **через сервер** по SSE — эфемерные токены Live API
браузерное соединение не принимают (проверено 22.08.2026, сокет закрывается с
1008), а постоянному ключу в браузере не место.

Прод работает на waitress (WSGI), где WebSocket невозможен в принципе — отсюда и
такая развязка.

## Что сохраняется

Всё, что можно измерить, и в разрезе каждой реплики: уверенность распознавания,
языковой состав, выдержка тишины до конца реплики, время первого токена модели,
токены на входе и выходе, задержка озвучки, длительность речи, слышимая пауза
«человек домолчал → собеседник заговорил», перебивания, статьи-источники в режиме
наставника. Плюс по сессии: стек моделей по факту (он подменяется на ходу при
отказе провайдера), медиана и худшая пауза, стоимость и **ставки, по которым она
посчитана** — тарифы меняются, а вопрос «сколько стоил вон тот прогон» задаётся
задним числом.

Список замеров закреплён тестом: `test_turn_keeps_every_measurement`.

## Автономный стенд — ЛОКАЛЬНЫЙ, в git его нет

Раздел отлаживался на отдельном стенде: свой aiohttp-сервер, сквозной прогон без
микрофона и прогон в настоящем Chrome с подставным микрофоном. В репозиторий он
не едет намеренно (`voice_trainer/.gitignore`): на сервере этот код мёртв, а
зависимости `aiohttp` в `requirements.txt` нет. Файлы стенда — `server.py`,
`e2e_check.py`, `browser_check.mjs`, `static/`, `samples/`.

Если стенд понадобится снова, его придётся восстановить у себя: раздел от него
не зависит, набор для сервера самодостаточен (проверено запуском тестов с
убранным стендом).

Дальше — описание того самого стенда, для истории замеров.

## Запуск стенда

```bash
python voice_trainer/server.py        # → http://127.0.0.1:8770
```

Микрофон браузер даёт только на `localhost` или по HTTPS — по IP в локальной сети
работать не будет.

Проверка без микрофона и без браузера (поднимает сервер сам, подаёт синтезированный
голос «стажёра», печатает замеры и оценку):

```bash
python voice_trainer/e2e_check.py
```

## Что выяснилось не так, как ожидалось

1. **У Soniox в нашем аккаунте нет ни одной TTS-модели.** `/v1/models` отдаёт только
   `stt-*`, `/v1/voices` — пустой список. По документации у Soniox казахский синтез
   есть, но на аккаунте он не подключён. Это меняет вывод отчёта по вендорам: Soniox
   закрывает нам только распознавание.
2. **`gemini-2.5-flash-preview-tts` отказывается говорить по-казахски** — отвечает
   `finishReason: OTHER` и ноль байт аудио. Казахский умеет `gemini-3.1-flash-tts-preview`.
   При этом через Live API казахский говорит и модель 2.5 — то есть дело было в
   конкретной TTS-модели, а не в языке.
3. **Обычный TTS не годится для диалога.** `generateContent` отдаёт готовый файл за
   5,0–6,5 с и не стримит. Поэтому озвучка сделана через Live API (`bidiGenerateContent`).
4. **Cloud Text-to-Speech в проекте GCP отключён** (`SERVICE_DISABLED`, проект
   `analog-delight-464908-g8`). Сервис-аккаунт рабочий, но включать API в чужом
   облаке без решения владельца я не стал.
5. **Многострочный ключ сервис-аккаунта ломает построчный парсер `.env`.** В
   `call_qa/config.py` он читается построчно, и `GOOGLE_APPLICATION_CREDENTIALS_CONTENT`
   (15 строк) приходит битым. В `env_local.py` загрузчик учитывает баланс скобок.

## Дефект, найденный браузерной проверкой

Пока перебивание отменяло ход, сказанное водителем не попадало в историю диалога —
и на каждом следующем ходу он называл новую фамилию: Сабитов, Ибрагимов, Каримов.
Персонаж рассыпался. Исправлено: при отмене хода уже произнесённое дописывается в
историю с пометкой «[перебит]». Это ровно тот класс ошибок, который не виден ни в
модульных тестах, ни в сквозном тесте без браузера.

## Слабое место прототипа

Пауза до ответа **3,9–4,5 с**. Для тренажёра это терпимо (живой водитель на линии
тоже думает), для боевого обзвона — нет. Складывается так: 1,3 с модель диалога +
1,4 с первый звук озвучки + ожидание конца первого предложения перед отправкой в
синтез. Куда это сокращать:

- Cloud TTS вместо Live API — стриминг с задержкой в сотни миллисекунд вместо 1,4 с.
- Отдавать в озвучку не законченное предложение, а первые 4–5 слов.
- Либо перейти на Live API целиком (речь в речь, без промежуточного текста) — тогда
  пропадает контроль над сценарием через системный промпт Claude, и это отдельное
  архитектурное решение.

## Устройство

| Файл | Что делает |
|---|---|
| `server.py` | aiohttp: раздаёт страницу, держит WS с браузером, гоняет Soniox / модель / озвучку |
| `scenarios.py` | персонажи водителей, правила «не помогать оператору», критерии оценки |
| `static/index.html` | интерфейс: выбор сценария, стенограмма, замеры, карточка оценки |
| `static/worklet.js` | захват микрофона, Float32 → Int16 |
| `e2e_check.py` | сквозная проверка без микрофона |
| `browser_check.mjs` | прогон в настоящем Chrome: вместо микрофона подставляется WAV |
| `env_local.py` | чтение секретов с поддержкой многострочных значений |
| `samples/` | образцы синтеза для проверки языков (в git не нужны) |

Сценарии специально лежат отдельным файлом и не смешаны с базой знаний. База знаний
отвечает «как оператор должен решить проблему», а водителю нужно обратное: чего не
говорить сразу и как реагировать на неверный вопрос. При смене голосовой платформы
эта часть переживёт переезд, а код транспорта — нет.

## Переключатели через переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `TRAINER_LLM` | `claude` | `claude` или `gemini` — кто играет водителя. При исчерпанном балансе переключение происходит само |
| `TRAINER_VOICE` | `live` | `live` (Live API, быстро) или `batch` (generateContent, медленно) |

| `TRAINER_GEMINI_MODEL` | `gemini-3.5-flash` | 3.7-flash регулярно отдаёт 503 «high demand» |
| `TRAINER_CLAUDE_MODEL` | `claude-sonnet-5` | |

## Три сценария в наборе

- **Отмена заказа, спокойный водитель** (3/10, ru) — базовая диагностика.
- **Не пришла выплата, раздражённый** (8/10, ru) — работа с негативом. Водитель
  утверждает, что звонит третий раз, хотя звонил один. Настоящая причина — смена
  номера телефона, и сам он об этом не скажет.
- **Непонятная проблема, казахский** (7/10, kk) — водитель объясняет путано, отвечает
  обрывками. Причина — истёкший техосмотр, связь с проблемой он не видит.
