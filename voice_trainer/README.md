# Тренажёр: раздел OTP

Голосовой разговор с ИИ и разбор после него. Раздел тестовый, доступен только
супер-админу, живёт по адресу `?view=voice_trainer`.

Два режима одной механики:

* **Водитель** — ИИ играет водителя такси, человек тренируется отвечать как
  оператор, в конце второй ИИ выставляет оценку по критериям сценария.
* **Наставник** — наоборот: человек спрашивает, ИИ отвечает как опытный оператор,
  опираясь на базу знаний. Свой поиск здесь НЕ строится: вызывается движок
  чат-помощника вики — тот же периметр статей (человек слышит только то, что ему
  разрешено читать), тот же гибридный поиск, тот же генератор.

Собран на том, что уже оплачено: распознавание — Soniox, база знаний — вики,
модель и озвучка — Vertex AI по сервисному аккаунту. Голосовой платформе (Vapi,
Retell, ElevenLabs) платить не за что: она продаёт именно эти слои.

## Где что лежит

| Файл | Что делает |
|---|---|
| `schema.py` | таблицы `trainer_sessions` / `trainer_turns` / `trainer_events` |
| `routes.py` | Blueprint `/api/trainer`, гейт супер-админа, оба режима, разбор |
| `scenarios.py` | персонажи водителей и критерии оценки |
| `src/components/trainer/TrainerView.jsx` | раздел на общих iOS-примитивах |
| `src/components/trainer/voice.js` | микрофон, сокет распознавания, воспроизведение |
| `src/components/trainer/trainerFormat.js` | правила показа замеров (покрыты тестом) |

Тесты: `pytest tests/test_trainer_schema.py tests/test_trainer_access.py
tests/test_trainer_voice_chain.py`, `npm run test:trainer`.

## Куда идёт звук

Микрофон подключается **напрямую к Soniox** по временному ключу на 10 минут:
поток непрерывный, и гонять его через наш сервер значило бы платить лишним кругом
на каждом кадре. Озвучка идёт **через сервер** по SSE: ни постоянному ключу, ни
сервисному аккаунту в браузере не место, а эфемерные токены Live API браузерное
соединение не принимает (проверено 22.08.2026, сокет закрывается с 1008).

Прод работает на waitress (WSGI), где WebSocket невозможен в принципе — отсюда и
такая развязка.

Поток озвучки: `start` (провайдер, модель, частота) → `audio`… → `done`. Событие
`error` означает, что звука не будет, и его обязан увидеть человек.

## Провайдеры идут цепочкой, а не поодиночке

Каждое звено перебирает провайдеров по порядку и берёт первого, кто ответил.

| Звено | Цепочка по умолчанию | Переменная |
|---|---|---|
| собеседник и разбор | `vertex` → `gemini` → `claude` | `TRAINER_LLM_CHAIN` |
| озвучка | `vertex` → `live` | `TRAINER_TTS_CHAIN` |

Vertex стоит первым не из предпочтения. **22.08.2026 раздел замолчал целиком:**
у ключа AI Studio кончились предоплаченные кредиты, и разом умерли все три
звена, которые на нём висели — роль водителя, разбор и озвучка. Vertex считает
обычным счётом Google Cloud и постоянного ключа не требует вовсе. Ключ AI Studio
остался вторым номером: вернутся кредиты — вернётся и он, без правки кода.

Правила переключения у озвучки жёсткие: сменить провайдера можно, **только пока
не прозвучало ни одного куска**. Дальше отказ обрывает реплику, но не начинает
её заново — иначе второй провайдер прочитал бы ту же фразу поверх первой.
Прозвучавшее при этом засчитывается в замеры.

Отказ звена **никогда не выглядит тишиной**: он приходит событием `error` с
текстом причины, ложится строкой в «Что пошло не так» и событием в журнал сессии
(`tts_failed`, `tts_cut`). До 22.08 этого не было: сервер досылал `done` с нулём
байт, и раздел сутки молчал, не сказав ни слова о причине.

## Собеседник не перебивает

Распознавание ставит точку по паузе в 600 мс. Этого мало: человек посреди
предложения думает дольше, и реплики уходили в модель обрывками — в базе так и
лежат «Ты уверен, что.», «Нужно делать всего лишь.», «Вижу то, что заказ был
полностью на.», «Акциясы бойынша.». Собеседник отвечал на половину фразы.

Поэтому после точки браузер выдерживает паузу, и если человек продолжил —
приклеивает сказанное к накопленному, а не заводит вторую реплику. Выдержка
**адаптивная**, потому что платить ею за каждую реплику незачем:

| фраза | ждём | почему |
|---|---|---|
| «Вы можете подсказать адрес?» | 300 мс | закончена: хватает слов, хвост не связка |
| «Ты уверен, что.» | 1200 мс | хвост-связка — продолжение почти наверняка будет |
| «Жеті қазына.» | 1200 мс | меньше трёх слов: это ещё не реплика |
| «Казына —» | 1200 мс | тире в конце |

Признак незаконченности — мало слов или хвост-связка (`DANGLING` в `voice.js`:
русские союзы и предлоги плюс казахские послелоги). Список не теоретический: в
нём ровно те хвосты, на которых прод обрывал живых людей. Значения выдержки
приходят с сервера в `/tokens` (`TRAINER_HOLD_SHORT_MS`, `TRAINER_HOLD_LONG_MS`),
чтобы подбирать их переменной окружения, а не пересборкой фронта; сколько
прождали, сохраняется в реплике (`hold_ms`) рядом с задержкой распознавания.

## Что наставник помнит

**В пределах разговора — последние 6 реплик**, ровно как чат-помощник вики: тот
же формат (`role` + `kind` + `text`), тот же размер окна, те же правила
обогащения запроса и уточнения. **Между разговорами памяти нет**: новая сессия
начинается с чистого листа, а прошлые видны только в «Журнале» и в модель не
попадают. Для тренажёра это осознанно — каждый прогон отдельный разговор.

До 22.08.2026 памяти не было и внутри разговора, хотя выглядело, будто есть.
История собиралась с одним ключом `kind`, без `role`, и движок её не узнавал:

* `enrich_query` ищет реплики с `role='user'` и не находил ни одной — короткое
  уточнение искалось БЕЗ темы разговора;
* сборка сообщений для модели считала ответы самого наставника репликами
  человека;
* правило вики «не переспрашивать после уточнения и после обогащённого запроса»
  не работало вовсе, потому что опирается на `kind` предыдущей реплики, а вид
  реплики нигде не сохранялся.

На проде это выглядело так: на «Жеті қазына» после вопроса про ту же акцию
наставник дважды переспросил «уточните вопрос» и так и не ответил, хотя акция в
вике есть. После правки на том же разговоре он отвечает полностью — даты,
условия, призы.

## Наставник отвечает голосом, а не текстом

Режим «Наставник» переиспользует движок чат-помощника вики целиком — поиск,
периметр, защиту от выдумки. Расхождений с ним ровно два, и оба про то, что
наставника СЛУШАЮТ.

**Форма ответа.** К системному промпту вики приписывается голосовое правило
(`scenarios.MENTOR_VOICE_RULES`), а не заменяет его. Промпт помощника требует
списков и таблиц Markdown — в интерфейсе они рисуются. Вслух это выходит боком
дважды: синтез читает звёздочки, а ответ на 1047 знаков — это 76 секунд
монолога. С правилом тот же вопрос даёт 353 знака и 1,9 с вместо 4,8 с.
Требование краткости отдельно уравновешено: без явного напоминания модель
переставала признаваться, что ответа в статьях НЕТ, и молча пересказывала
соседние требования.

**Модель.** У помощника первым стоит `gemini-3-flash-preview`, выбранный по
качеству, — задержка там не решала. Наставнику она решает. Замер 22.08.2026 на
пяти случаях (есть ответ / ответа нет / конкретное число / нет инструкции /
казахский), по два прогона:

| модель | медиана | почему так |
|---|---|---|
| `gemini-3-flash-preview` | 2071 мс | модель помощника вики, теперь резерв |
| **`gemini-3.5-flash`** | **1174 мс** | взята: та же честность и те же числа |
| `gemini-3.5-flash-lite` | 929 мс | не взята: ужимает ответ до потери смысла |

flash-lite быстрее всех, но на «что делать, если не прошёл фотоконтроль» отвечает
только «в статьях этого нет, обратитесь к супервайзеру» и теряет то, что рядом
известно, — а наставник затем и нужен, чтобы это рассказать. Вернуть цепочку
вики — пустая `TRAINER_MENTOR_CHAIN`.

## Откуда бралась пауза наставника

Замеры прода 22.08.2026, по шагам (сервер кладёт их в саму реплику, `raw.stages`):

Все числа — с боевого сервера, прогретого (первая реплика после деплоя платит
за токен сервис-аккаунта и рукопожатия, там на 300–700 мс больше):

| шаг | было | стало | что сделано |
|---|---|---|---|
| права и периметр | 3 запроса в базу на каждую реплику | **0 мс** со второй реплики | считается раз на разговор, сбрасывается при создании сессии |
| вектор запроса | считался в `asia-southeast1` | **56–104 мс** | свой регион вики `europe-west3` + постоянное соединение |
| поиск | 442 мс | 21–172 мс | следствие прогретого соединения и кеша периметра |
| модель | 4084 мс | **1111–1518 мс** | голосовая форма ответа + `gemini-3.5-flash` |
| первый звук озвучки | 570 мс | 509–545 мс | постоянное соединение к Vertex |
| **вся пауза до голоса** | **~4,7 с** | **1,9–2,4 с** | |

Заодно ответ перестал быть монологом: на вопросе про фотоконтроль было 1047
знаков (76 секунд речи), стало 157 (9,6 секунды).

Регион вектора — отдельная история. Прод стоит во Франкфурте, а `call_qa` по
умолчанию считает векторы в Сингапуре, и каждый вопрос летал через полмира.
Общую переменную `VERTEX_REGION` трогать нельзя: она входит в `config_hash`
контракта, на который ключуется база знаний разбора звонков, — смена региона там
означала бы «векторов нет, считай заново». У вики контракт состоит из
provider/model/dim и региона не содержит, а `europe-west3` отдаёт БИТ-В-БИТ те
же векторы (косинус к посчитанному индексу 1,00000000 на русском и казахском).
Поэтому регион переехал только у вики, переменной `WIKI_EMBED_REGION`.

Что ещё лежит на столе и не сделано:

* **склеить `/turn` и `/speak` в один поток** — сейчас браузер делает два
  запроса подряд, и второй стоит лишнего обхода (~150 мс с прогретым
  соединением);
* **начинать озвучку с первой фразы, не дожидаясь конца ответа** — это ещё
  около секунды, но защита от выдумки проверяет ответ ЦЕЛИКОМ: числа, которых
  нет во фрагментах, отменяют весь ответ. Начав говорить раньше проверки,
  тренажёр иногда учил бы тому, что сам потом забирает назад. Не делаю без
  отдельного решения;
* **Cloud Text-to-Speech вместо Gemini TTS** — первый звук в сотни миллисекунд
  вместо 510–545 мс, и дешевле; нужно включить сервис в проекте GCP.

Отдельно про **язык ответа**: он определяется кодом (`wiki/ai/answer.detect_language`),
и казахские буквы считаются ПО СЛОВАМ. Раньше хватало одной буквы где угодно, и
русский вопрос «Расскажи всё про акцию «Жетіқазына»» объявлялся казахским — из-за
названия акции. Помощник честно отвечал по-казахски человеку, спросившему
по-русски. Название на другом языке это ИМЯ, а не язык вопроса. У реплики из
одного-двух слов языка нет вовсе, и он берётся из предыдущей реплики человека:
в голосовом режиме короткие реплики норма, а не исключение.

Чего сделать НЕЛЬЗЯ, чтобы не искать заново: озвучка `gemini-3.1-flash-tts-preview`
и модель `gemini-3-flash-preview` живут ТОЛЬКО в `global` — в `europe-west*` их
нет (404), региональным закреплением их не ускорить. И длина ответа решает
больше, чем длина запроса: 4521 токен на входе дал 970 мс, а 1939 токенов —
1463 мс, потому что во втором случае модель написала вчетверо больше.

## Что сохраняется

Всё, что можно измерить, и в разрезе каждой реплики: уверенность распознавания,
языковой состав, выдержка тишины до конца реплики, время первого токена модели,
токены на входе и выходе, задержка озвучки, длительность речи, слышимая пауза
«человек домолчал → собеседник заговорил», перебивания, статьи-источники в режиме
наставника. Плюс по сессии: стек моделей по факту (он подменяется на ходу при
отказе провайдера), медиана и худшая пауза, стоимость и **ставки, по которым она
посчитана** — тарифы меняются, а вопрос «сколько стоил вон тот прогон» задаётся
задним числом.

Список замеров закреплён тестом: `test_turn_keeps_every_measurement`.

## Автономный стенд — ЛОКАЛЬНЫЙ, в git его нет

Раздел отлаживался на отдельном стенде: свой aiohttp-сервер, сквозной прогон без
микрофона и прогон в настоящем Chrome с подставным микрофоном. В репозиторий он
не едет намеренно (`voice_trainer/.gitignore`): на сервере этот код мёртв, а
зависимости `aiohttp` в `requirements.txt` нет. Файлы стенда — `server.py`,
`e2e_check.py`, `browser_check.mjs`, `static/`, `samples/`.

Если стенд понадобится снова, его придётся восстановить у себя: раздел от него
не зависит, набор для сервера самодостаточен (проверено запуском тестов с
убранным стендом).

Дальше — описание того самого стенда, для истории замеров.

```bash
python voice_trainer/server.py        # → http://127.0.0.1:8770
```

### Замеры на самом проде, 22.08.2026

Полный прогон обоих режимов через боевой API (сессии 11 и 12 в журнале), звук
проверен обратным прогоном через Soniox:

| Что | Водитель | Наставник |
|---|---|---|
| ответ модели | 1,07 с | 4,08 с (с поиском по вике) |
| первый звук озвучки | **0,59–0,86 с** | **0,57 с** |
| распознали обратно | WER 0 % | WER 7 % (разница в «ё» и запятой) |
| разбор в конце | 40 баллов, без ошибок | не предусмотрен |
| стоимость сессии | $0,0033 | $0,0054 |

**Прод быстрее машины разработчика втрое**: 0,6–0,9 с против 1,3–2,9 с. Render и
Vertex стоят близко друг к другу, а замеры «слабого места» ниже (пауза 3,9–4,5 с)
сняты с ноутбука через домашний канал. Настоящая пауза «человек домолчал →
собеседник заговорил» измеряется только с живым микрофоном и лежит в
`voice_to_voice_p50` сессии.

## Что выяснилось не так, как ожидалось

1. **У Soniox в нашем аккаунте нет ни одной TTS-модели.** `/v1/models` отдаёт только
   `stt-*`, `/v1/voices` — пустой список. По документации у Soniox казахский синтез
   есть, но на аккаунте он не подключён. Это меняет вывод отчёта по вендорам: Soniox
   закрывает нам только распознавание.
2. **`gemini-2.5-flash-preview-tts` отказывается говорить по-казахски** — отвечает
   `finishReason: OTHER` и ноль байт аудио. Казахский умеет `gemini-3.1-flash-tts-preview`.
   При этом через Live API казахский говорит и модель 2.5 — то есть дело было в
   конкретной TTS-модели, а не в языке.
3. **Обычный TTS не годится для диалога.** `generateContent` отдаёт готовый файл за
   5,0–6,5 с и не стримит. Поэтому озвучка сделана через Live API (`bidiGenerateContent`).
4. **Cloud Text-to-Speech в проекте GCP отключён** (`SERVICE_DISABLED`, проект
   `analog-delight-464908-g8`). Сервис-аккаунт рабочий, но включать API в чужом
   облаке без решения владельца я не стал.
5. **Многострочный ключ сервис-аккаунта ломает построчный парсер `.env`.** В
   `call_qa/config.py` он читается построчно, и `GOOGLE_APPLICATION_CREDENTIALS_CONTENT`
   (15 строк) приходит битым. В `env_local.py` загрузчик учитывает баланс скобок.

## Дефект, найденный браузерной проверкой

Пока перебивание отменяло ход, сказанное водителем не попадало в историю диалога —
и на каждом следующем ходу он называл новую фамилию: Сабитов, Ибрагимов, Каримов.
Персонаж рассыпался. Исправлено: при отмене хода уже произнесённое дописывается в
историю с пометкой «[перебит]». Это ровно тот класс ошибок, который не виден ни в
модульных тестах, ни в сквозном тесте без браузера.

## Что блокирует и требует решения владельца

Ни одно из этого больше не мешает разделу работать: и модель, и озвучка ушли на
Vertex, который оплачен обычным счётом Google Cloud.

| Что | Что это меняет | Что нужно |
|---|---|---|
| **Кредиты AI Studio исчерпаны** | `Your prepayment credits are depleted`. Ключ `GEMINI_API_KEY` жив, но по нему не отвечает ничего — он остаётся вторым номером в обеих цепочках | пополнить на ai.studio/projects |
| **Баланс Anthropic исчерпан** | `credit balance is too low` — Claude третьим номером в цепочке собеседника, до него дело не доходит | пополнить баланс |
| **Лимит одновременных сессий Soniox** | по докам 4 потока распознавания на проект. Группа стажёров упрётся в 429 | заявка в support на поднятие |
| **Регион Soniox** | сейчас US. EU/JP включаются только заявкой и выбираются при создании проекта, задним числом не меняются | заявка, если нужен меньший RTT |
| **Cloud TTS отключён в проекте GCP** | дал бы `kk-KZ` со стримингом в сотни миллисекунд и дешевле — это следующий шаг по сокращению паузы | включить `texttospeech.googleapis.com` в `analog-delight-464908-g8` |

## Слабое место прототипа

Пауза до ответа. Замер с ноутбука 21.08 давал **3,9-4,5 с**; после переезда на
Vertex прод складывает 1,07 с (модель) + 0,59 с (первый звук) + выдержка тишины
0,6 с ≈ **2,3 с**. Для тренажёра терпимо и было, и стало (живой водитель на линии
тоже думает), но сокращать есть куда:

- **Cloud TTS** — стриминг с задержкой в сотни миллисекунд и дешевле; нужно
  включить `texttospeech.googleapis.com` в проекте GCP.
- Отдавать в озвучку не законченное предложение, а первые 4-5 слов.
- Либо перейти на Live API целиком (речь в речь, без промежуточного текста) — тогда
  пропадает контроль над сценарием через системный промпт, и это отдельное
  архитектурное решение. Плюс Live API у нас сейчас недоступен вовсе: на Vertex
  его нет, а по ключу AI Studio кончились кредиты.

## Устройство

| Файл | Что делает |
|---|---|
| `server.py` | aiohttp: раздаёт страницу, держит WS с браузером, гоняет Soniox / модель / озвучку |
| `scenarios.py` | персонажи водителей, правила «не помогать оператору», критерии оценки |
| `static/index.html` | интерфейс: выбор сценария, стенограмма, замеры, карточка оценки |
| `static/worklet.js` | захват микрофона, Float32 → Int16 |
| `e2e_check.py` | сквозная проверка без микрофона |
| `browser_check.mjs` | прогон в настоящем Chrome: вместо микрофона подставляется WAV |
| `env_local.py` | чтение секретов с поддержкой многострочных значений |
| `samples/` | образцы синтеза для проверки языков (в git не нужны) |

Сценарии специально лежат отдельным файлом и не смешаны с базой знаний. База знаний
отвечает «как оператор должен решить проблему», а водителю нужно обратное: чего не
говорить сразу и как реагировать на неверный вопрос. При смене голосовой платформы
эта часть переживёт переезд, а код транспорта — нет.

## Три сценария в наборе

- **Отмена заказа, спокойный водитель** (3/10, ru) — базовая диагностика.
- **Не пришла выплата, раздражённый** (8/10, ru) — работа с негативом. Водитель
  утверждает, что звонит третий раз, хотя звонил один. Настоящая причина — смена
  номера телефона, и сам он об этом не скажет.
- **Непонятная проблема, казахский** (7/10, kk) — водитель объясняет путано, отвечает
  обрывками. Причина — истёкший техосмотр, связь с проблемой он не видит.
