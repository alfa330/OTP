# Требование к API: конкурс «Топ по регистрациям»

Конкурс: регистрации 07.08.2026–07.09.2026, засчитывается водитель, совершивший
хотя бы одну **завершённую** поездку до 11.09.2026 включительно.
Участники — операторы двух групп: **Чаты** и **Линия**.
Нам нужен эндпоинт, куда мы отправляем период и получаем засчитанные регистрации.

## 1. Запрос (наша сторона → CRM)

```
POST {base}/partners/registrations-contest
X-Integration-Token: <токен>
Content-Type: application/json

{
  "registered_from": "2026-08-07",   // дата регистрации водителя, включительно
  "registered_to":   "2026-09-07",   // включительно
  "trip_deadline":   "2026-09-11",   // крайняя дата завершённой поездки, включительно
  "page": 1,
  "per_page": 500
}
```

Даты — календарные, часовой пояс Asia/Almaty (UTC+5).
`trip_deadline` отдельным полем, потому что окно регистраций и окно поездок не совпадают.

## 2. Ответ (CRM → нам)

Одна строка = один засчитанный водитель. Агрегат по операторам мы считаем сами —
он нужен нам «сырым», чтобы отработать тай-брейк и показать расшифровку.

```json
{
  "total": 1234,
  "page": 1,
  "per_page": 500,
  "has_more": true,
  "rows": [
    {
      "operator_id":    "1042",                       // стабильный ID оператора в CRM
      "operator_login": "a.ivanov@company.kz",        // логин/почта — для сопоставления с iCORE
      "operator_name":  "Иванов Иван",
      "operator_group": "chat",                       // chat | line, если CRM это знает

      "driver_id":      "DRV-889201",
      "driver_phone":   "+77011234567",
      "driver_name":    "Петров Пётр",

      "registered_at":  "2026-08-07T10:15:00+05:00",  // время регистрации в CRM
      "first_trip_at":  "2026-08-09T18:40:00+05:00",  // первая ЗАВЕРШЁННАЯ поездка
      "trips_count":    3
    }
  ]
}
```

## 3. Правила отбора — на стороне CRM

1. Только водители, зарегистрированные **по реферальной ссылке оператора** в CRM.
2. В выдачу попадают только те, у кого есть завершённая поездка с `first_trip_at <= trip_deadline`.
   Без поездки — строку не отдавать.
3. Дедупликация по `driver_phone` и `driver_id`: водитель отдаётся **один раз**, тому оператору,
   который зарегистрировал его первым (минимальный `registered_at`). Повторные регистрации не отдаём.

## 4. Технические требования

- JSON, UTF-8; даты — ISO-8601 со смещением таймзоны.
- Метод идемпотентный и доступен для повторных вызовов: мы будем опрашивать раз в сутки
  (ночью) и по кнопке «Обновить» в интерфейсе; данные — не старше суток.
- Пагинация обязательна (`page`/`per_page` + `has_more`); подтвердите максимум `per_page` и rate limit.
- Ошибки: корректный HTTP-код + тело `{"error_code": ..., "message": "..."}`.
- Нужен тестовый стенд и токен для теста до старта конкурса.

## 5. Вопросы к вашей стороне

1. Какой идентификатор оператора стабильный — числовой `id`, логин или почта?
   По нему мы связываем строку с оператором iCORE.
2. Знает ли CRM группу оператора (Чаты / Линия)? Если нет — сопоставим сами по нашей структуре.
3. Что у вас считается «завершённой поездкой» (какой статус заказа) и учитываются ли отменённые/фрод.

## 6. Дополнение от 07.08.2026: регистрации без поездки (`include_no_trip`)

Операторам нужно видеть не только засчитанных водителей, но и **общее число своих
регистраций** — сколько водителей уже зарегистрировано и ждёт первую поездку.

Просим поддержать в том же эндпоинте необязательный флаг запроса:

```json
{ ..., "include_no_trip": true }
```

- `include_no_trip: true` → в `rows` дополнительно попадают водители,
  зарегистрированные в окне `registered_from…registered_to`, у которых **ещё нет**
  завершённой поездки (или она была позже `trip_deadline`). У таких строк
  `first_trip_at: null`, `trips_count: 0` — по этому признаку мы отличаем их
  от засчитанных.
- Правило дедупликации то же: водитель отдаётся один раз, тому оператору,
  который зарегистрировал его первым.
- Флаг не передан или `false` → поведение как сейчас (только засчитанные),
  ничего не ломается.

Мы уже шлём `include_no_trip: true` в каждом запросе (сейчас вы его игнорируете —
это безопасно). Как только флаг заработает, счётчик регистраций появится в
интерфейсе автоматически, без релиза с нашей стороны.
