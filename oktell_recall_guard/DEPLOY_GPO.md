# Oktell Recall Guard: установка групповой политикой

Инструкция для администраторов домена. Программа ограничивает время в статусе
«Перезвон» в веб-клиенте Oktell; ставится на компьютеры операторов.

## Коротко

- Пакет — `OktellRecallGuard-<версия>.msi`, его выдаёт разработка.
- Назначается **компьютерам** через «Установку программ» в GPO. Ставится при
  загрузке от имени системы, без окон и без участия сотрудника.
- **SmartScreen при этом не появляется.** Он проверяет только файлы с пометкой
  «скачано из интернета» (Mark of the Web), а файлы, установленные групповой
  политикой, такой пометки не получают. Предупреждение, которое видели
  сотрудники, относится к ручному скачиванию exe из iCORE.
- Подпись кодом нужна не ради SmartScreen: с ней вместо «Неизвестный издатель»
  стоит имя организации, и AppLocker/WDAC можно разрешить программу по
  издателю. Подписанный пакет разработка соберёт, когда будет сертификат (шаг 1);
  до этого пилот можно проводить и без подписи.

## Что ставит пакет

| Что | Где |
|---|---|
| Программа | `C:\Program Files\Oktell Recall Guard\OktellRecallGuard.exe` |
| Запуск при входе любого пользователя | `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`, значение `OktellRecallGuardMachine` = `"…\OktellRecallGuard.exe" --deployed` |

Служб, заданий планировщика, драйверов и своих действий установщика (custom
actions) в пакете нет. Прав администратора программа для работы не требует.

При входе пользователя программа из Program Files:

1. кладёт рабочую копию в `%LOCALAPPDATA%\OktellRecallGuard\` — только если
   там её нет или она старее;
2. создаёт на рабочем столе ярлык «Oktell» (через него сотрудник открывает
   Oktell);
3. запускает рабочую копию и завершается.

Рабочая копия лежит в профиле, потому что обновляется сама: раз в 6 часов
сверяется с сервером iCORE, скачивает только более новую версию и ставит её
лишь при совпадении контрольной суммы SHA-256. Писать в Program Files обычный
пользователь не может, поэтому новый MSI для обновлений не нужен.

## Требования к компьютерам

- Windows 10 или 11, 64-битная.
- Google Chrome или Microsoft Edge.
- HTTPS до сервера iCORE, до `storage.googleapis.com` (оттуда скачиваются
  обновления) и до веб-клиента Oktell.
- Пользователям разрешён запуск `powershell.exe`: через него создаётся ярлык.
- Если включён AppLocker или WDAC — разрешите
  `%LOCALAPPDATA%\OktellRecallGuard\OktellRecallGuard.exe`. Лучше правилом по
  издателю (нужна подпись): правило по хешу ломается на каждом обновлении.

## Шаг 1. Сертификат для подписи

Нужен один раз, дальше разработка подписывает каждую сборку сама.

**Вариант А — внутренний центр сертификации (AD CS).** Рекомендуем: бесплатно,
а корневой сертификат Enterprise CA компьютеры домена уже считают доверенным.

1. На ЦС: «Шаблоны сертификатов» → «Создать» → «Выдаваемый шаблон сертификата»
   → «Подписание кода» (Code Signing). Если шаблон не разрешает экспорт ключа,
   сделайте его копию с включённым «Разрешить экспорт закрытого ключа» и
   выдавайте копию.
2. Выпустите сертификат и экспортируйте его **с закрытым ключом** в `.pfx`.
   Машина сборки не в домене, поэтому разработке нужен файл `.pfx` и пароль
   к нему, переданные отдельно друг от друга.
3. Если ЦС не Enterprise (корень не публикуется в AD сам), разошлите корневой
   сертификат GPO: Конфигурация компьютера → Политики → Конфигурация Windows →
   Параметры безопасности → Политики открытого ключа → Доверенные корневые
   центры сертификации.

Ограничение: вне домена (личный ноутбук, скачивание из iCORE) такую подпись
Windows не признаёт.

**Вариант Б — сертификат от публичного ЦС** (OV: Sectigo, DigiCert, GlobalSign,
SSL.com, Certum). Нужен, только если программу ставят скачиванием на
компьютеры вне домена. Учтите:

- с 1 июня 2023 года ключ выдают только на аппаратном токене или в облачном
  HSM — файлом `.pfx` его не получить;
- SmartScreen у скачанного файла он сразу не снимет: репутация набирается
  скачиваниями, а у программы на несколько десятков компьютеров её может не
  набраться никогда. EV-сертификаты мгновенной репутации тоже больше не дают
  (с марта 2024 года).

**Azure Artifact Signing** (бывший Trusted Signing) организациям из Казахстана
недоступен: по [документации Microsoft](https://learn.microsoft.com/azure/artifact-signing/quickstart#prerequisites)
публичные сертификаты выдаются организациям из США, Канады, ЕС,
Великобритании, Австралии, Новой Зеландии, Японии, Южной Кореи, Сингапура,
Швейцарии, Норвегии и Израиля.

## Шаг 2. Общая папка для пакета

- Положите `.msi` в общую папку, у которой **и на уровне общего доступа, и в
  NTFS** есть чтение для группы «Компьютеры домена» (Domain Computers):
  пакет забирает учётная запись компьютера, а не пользователя.
- В GPO путь указывается только в UNC-виде (`\\сервер\папка\файл.msi`), не
  буквой сетевого диска.
- Имя файла потом не меняйте: GPO запоминает путь.

## Шаг 3. Групповая политика

1. В «Управлении групповой политикой» создайте GPO «Oktell Recall Guard» и
   свяжите с OU компьютеров операторов (или оставьте в фильтре безопасности
   только группу этих компьютеров). Программа ставится **для всех, кто входит
   на компьютер**, поэтому назначать её стоит только компьютерам операторов.
2. Конфигурация компьютера → Политики → Конфигурация программ → Установка
   программ → «Создать» → «Пакет» → UNC-путь к `.msi` → «Назначенный».
3. Рекомендуется в той же GPO: Конфигурация компьютера → Политики →
   Административные шаблоны → Система → Вход в систему → «Всегда ждать сеть
   при запуске и входе в систему» → «Включено». Без этого установка на
   Windows 10/11 откладывается и может потребовать вторую перезагрузку.
4. На пилотном компьютере: `gpupdate /force`, затем **перезагрузка** (не
   «Завершение работы» — при быстром запуске политики при включении не
   применяются).

## Проверка на пилотном компьютере

1. «Параметры» → «Приложения»: есть «Oktell Recall Guard».
2. `C:\Program Files\Oktell Recall Guard\OktellRecallGuard.exe` → «Свойства» →
   «Цифровые подписи»: издатель — ваша организация (если пакет подписан).
3. Автозапуск прописан:
   `reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run /v OktellRecallGuardMachine`
4. После входа оператора: на рабочем столе ярлык «Oktell», в
   `%LOCALAPPDATA%\OktellRecallGuard\install.log` строка вида
   `Вход пользователя: машинная копия 1.0.16, у пользователя нет → install`.
5. Оператор открывает Oktell ярлыком — в iCORE, в разделе «Ограничитель
   Перезвона» → «Сотрудники», программа у него отмечена как работающая.

Если пакет не встал: журнал «Приложение», источник `MsiInstaller`
(11707 — установлено, 11708 — ошибка), и журнал «Система», источник
`Application Management Group Policy`.

## Новая версия пакета

Обновления программы приходят сами, новый MSI для них не нужен. Разработка
выдаст новый пакет, только если изменится сама установка. Тогда в той же GPO
добавьте его и на вкладке «Обновления» укажите прежний пакет с вариантом
обновления поверх существующего (Package can upgrade over the existing
package). Пакет сам находит и снимает прежнюю версию. Пакет более старой версии
поверх новой не встанет.

## Удаление

1. В GPO: пакет → «Все задачи» → «Удалить» → вариант немедленного удаления
   у пользователей и с компьютеров (Immediately uninstall the software from
   users and computers).
2. После перезагрузки компьютера пакет снимается: исчезают файл в Program Files
   и значение автозапуска. При входе программа больше не запускается.
3. Ярлык «Oktell» на рабочем столе остаётся до первого нажатия: копия в профиле
   видит, что пакет снят, убирает ярлык и останавливается, Oktell при этом не
   открывается. Логи в `%LOCALAPPDATA%\OktellRecallGuard\` остаются для разбора.

## Другие системы раскатки

Тот же пакет подходит для SCCM, Intune и PDQ:

```bat
msiexec /i OktellRecallGuard-1.0.16.msi /qn /l*v C:\Windows\Temp\OktellRecallGuard.log
msiexec /x OktellRecallGuard-1.0.16.msi /qn
```
